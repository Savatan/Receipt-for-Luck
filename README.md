# Чек на удачу

Веб-приложение промо-акции для регистрации и проверки кассовых чеков. Покупатель создаёт аккаунт, отправляет реквизиты чека и отслеживает результат проверки в личном кабинете. Модератор проверяет чеки через стандартную административную панель Django.

## Технологии

- Python 3.12
- Django
- PostgreSQL 16
- HTML, CSS и JavaScript без обязательного фронтенд-фреймворка
- Docker Compose

## Возможности

### Покупатель

- Регистрация и вход на базе стандартной системы аутентификации Django.
- Форма регистрации чека с ФН, ФД, ФП, датой и временем покупки и суммой.
- Клиентская проверка обязательных полей и форматов до отправки.
- Отправка формы через `fetch`; результат и ошибки показываются на странице без перезагрузки.
- Серверная валидация периода акции, суммы и цифровых реквизитов.
- Защита от повторной регистрации чека по сочетанию ФН + ФД + ФП.
- Личный кабинет с историей только собственных чеков, сортировкой от новых к старым и пагинацией по 10 записей.
- Отображение статуса и причины отказа.

### Модератор

- Стандартная Django Admin для пользователей с доступом к админке.
- Изменение статуса чека на «Принят» или «Отклонён».
- Причина отказа обязательна для отклонённого чека.
- Выгрузка выбранных принятых чеков в CSV.

### API и дополнительные функции

- `GET /api/receipts/` возвращает чеки только текущего авторизованного пользователя в JSON.
- Неавторизованный запрос получает ответ `401`.
- Параметры запроса не позволяют получить чеки другого пользователя.
- Разбор строки с параметрами QR-кода `t`, `s`, `fn`, `i`, `fp` с автозаполнением формы.
- Статусы в личном кабинете обновляются без полной перезагрузки страницы.
- Добавлены тесты валидации и проверки доступа к API.
- Интерфейс регистрации и личного кабинета адаптирован для мобильной ширины 375 px и ориентирован на предоставленный макет Figma.

## Запуск через Docker Compose

Потребуются установленный Docker Desktop или Docker Engine с Compose.

1. Скачайте репозиторий и перейдите в его корневую папку.
2. Создайте файл локальных настроек:

   ```bash
   cp .env.example .env
   ```

3. При необходимости откройте `.env` и настройте даты акции, часовой пояс и секретный ключ Django.
4. Соберите и запустите приложение:

   ```bash
   docker compose up --build
   ```

5. Откройте сайт: <http://localhost:8000/>.
6. Для входа в административную панель откройте <http://localhost:8000/admin/>.

Создать пользователя с правами суперпользователя можно в отдельном терминале:

```bash
docker compose exec web python manage.py createsuperuser
```

Остановка контейнеров:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume. Для удаления контейнеров и всех данных базы используйте `docker compose down -v`.

## Настройки окружения

Все переменные задаются в `.env`. Шаблон находится в `.env.example`.

| Переменная | Назначение |
|---|---|
| `DJANGO_SECRET_KEY` | Секретный ключ Django. Для размещения вне локальной разработки задайте собственное случайное значение. |
| `DJANGO_DEBUG` | Режим отладки. Для production установите `0`. |
| `DJANGO_ALLOWED_HOSTS` | Список разрешённых хостов через запятую. |
| `POSTGRES_DB` | Имя базы данных PostgreSQL. |
| `POSTGRES_USER` | Пользователь PostgreSQL. |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL. |
| `POSTGRES_HOST` | Хост базы данных. В Docker Compose используется `db`. |
| `POSTGRES_PORT` | Порт PostgreSQL. |
| `CAMPAIGN_START_DATE` | Первый календарный день акции в формате `YYYY-MM-DD`. |
| `CAMPAIGN_END_DATE` | Последний календарный день акции в формате `YYYY-MM-DD`. |
| `CAMPAIGN_TIME_ZONE` | Часовой пояс, в котором интерпретируются границы акции и время покупки. По умолчанию `Europe/Moscow`. |

Не публикуйте `.env` с настоящими секретами и паролями в GitHub.

## Проверка тестов

Запустить тесты внутри контейнера:

```bash
docker compose exec web python manage.py test
```

Если приложение ещё не запущено, сначала выполните `docker compose up --build`. Тесты проверяют основные правила валидации чеков и изоляцию данных пользователей в API.

## Решения по спорным вопросам

- **Границы акции.** Начальная и конечная даты включены в период акции. Календарные даты задаются переменными `CAMPAIGN_START_DATE` и `CAMPAIGN_END_DATE`; дата и время покупки интерпретируются в часовом поясе `CAMPAIGN_TIME_ZONE`, независимо от часового пояса браузера.
- **Повторная отправка.** Сочетание ФН + ФД + ФП уникально для всей системы. Повторно зарегистрировать тот же чек нельзя, в том числе если предыдущая попытка была отклонена. Отклонённый чек остаётся в истории, а модератор может изменить его статус через админку.
- **Статус нового чека.** Каждый новый чек получает статус «На проверке» на сервере; клиент не может назначить себе статус.
- **Причина отказа.** Для статуса «Отклонён» причина обязательна.
- **Доступ к данным.** Кабинет и API выбирают записи по текущему авторизованному пользователю. Идентификатор другого пользователя в параметрах запроса не влияет на выборку.
- **Реквизиты.** ФН, ФД и ФП принимают только цифры; для них установлен максимальный размер 32 символа. Минимальная сумма чека — 1000 ₽.

## Структура проекта

```text
lucky_receipt/       настройки Django и корневые маршруты
receipts/            модель чека, формы, представления, API, админка и тесты
receipts/migrations/ миграции базы данных
receipts/static/     CSS и JavaScript
 templates/          HTML-шаблоны страниц
Dockerfile           образ веб-приложения
compose.yaml         приложение и PostgreSQL
.env.example         пример переменных окружения
manage.py            команды Django
```

## Что не входит в задание

- Загрузка фотографии чека.
- Отдельный интерфейс модератора вне Django Admin.
- Интеграция с внешним оператором фискальных данных.
- Production-развёртывание с доменом, HTTPS, резервным копированием и внешним хранилищем статики.

## Работа с ИИ

ИИ использовался для адаптивной вёрстки. Результаты сверялись с условиями задания, в особенности с серверной проверкой периода акции, уникальностью фискальных реквизитов и ограничением API данными текущего пользователя.
